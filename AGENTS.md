# Разработка продукта

При начале самостоятельной задачи или возобновлении после перерыва выполнить `python3 scripts/product.py preflight`, затем читать документы с диска. Уточнения и промежуточные ответы той же задачи не запускают новый синк. Частота, размер проверки и завершение — [общий цикл](template/standards/task-validation.md). При blocked сохранить работу; после fast-forward перечитать инструкции. Без связи явно указывать local SHA и отсутствие подтверждения свежести.

Завершённые разрешённые изменения продукта сохранять коммитами и отправлять в origin/main: `git push origin HEAD:main`. Правило относится к продукту; компании получают только изолированный выпуск. Состояние подключения — в приватном PLAN и задаче разработки.

Документы разработки хранятся вне публичного репозитория и не копируются в компанию. Получить локальное расположение командой `git config --get cws.developmentRoot`; читать в нём README.md → PLAN.md → соответствующую work/<id>/task.md. Если расположение не задано, уточнить его у сопровождающего до разработки; не создавать публичную копию. Для настройки использовать только `git config --local cws.developmentRoot /absolute/private/path`. В чистом публичном clone отсутствие этих документов не является отказом runtime компании. Канонический комплект компании находится только в template/. scripts/product.py обслуживает выпуск; проверки продукта — checks/. Не добавлять сюда данные компаний. Не менять сайт, общие host-настройки или исследовательские основания. Выпускать только split-историю template в отдельный release-only repo. Независимые проверки по унаследованной политике; проверяющие только читают. Явно порученные исполнители меняют только свои файлы в изолированных worktree; дети не создают детей.

Python: небольшие модули по изменчивым контрактам; CLI без shell=True/eval и исполнения YAML-команд. Один атомарный механизм записи и lock; одна библиотека проверки; одна доставка. Детерминированные проверки обязаны отвергать плохие примеры. Полномочия и неизвестные бизнес-определения не брать из названий функций. Не заявлять live/native/полевой успех по локальному тесту. Проверки: python3 -m unittest discover -s checks -v.

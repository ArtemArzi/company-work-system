## P0: уточнение реализации до зависимого кода

- Отдельный Git-продукт: `/home/artem/projects/work/studio/products/company-work-system`. Родительский Git уже исключает эту зону. `template/` — один канонический копируемый комплект; product PLAN/README и свидетельства не входят в компанию.
- Python 3.12+, PyYAML 6.x, Git 2.43+; без сервера, БД и нового универсального движка. Один CLI вызывает узкие подготовленные операции; YAML читается агентом и валидируется, произвольные команды из YAML не исполняются.
- Выбранная альтернатива Copier: связанная история Git. `git subtree split --prefix=template` выпускает основу в ОТДЕЛЬНЫЙ release-only bare repo: только split история, без refs/objects продуктовой разработки. Компании клонируют и обновляют только этот repo, сохраняют общий предок. Проверять все достижимые refs/history/blob paths, а не только HEAD. Обновление — штатное трёхстороннее merge в отдельном кандидате. Проверить две компании до фиксации выбора. Никаких template tasks, установки архивов, submodules или force-push.
- Все три доставки используют одну программу: свежая целевая ветка → отдельный кандидат → общие проверки → обычный fast-forward push → чтение SHA и файлов из удалённой ветки. По умолчанию разрешены только локальные учебные bare repo; внешний remote требует явной действующей настройки компании. Грязное дерево не очищается, конфликт остаётся в кандидате; неизвестный исход push сверяется до повтора. Смысловые изменения метода требуют принятого решения у владельца, технический merge сам по себе его не доказывает.
- Форматы версии 1: company/config.yaml (ID/источники/полномочия/профили/функции/активные стандарты); work/<id>/task.json (единственное машинное состояние задачи, история, входы/результаты/ошибки/проверки/продолжение); README блока содержит маршруты, без второго статуса. task.md при наличии — вход к task.json, не независимый статус. ID `[a-z][a-z0-9-]{1,63}`. Результаты с происхождением, периодом, единицами, полнотой и точными hashes зависимостей.
- Техническое выполнение: draft/active/waiting/blocked/verified/cancelled; доставка: local/pending/delivered; применение и эффект: unknown/observed с отдельным свидетельством. Неизвестное не равно нулю или разрешению. Автоматическое исправление имеет технический конечный предел; бизнес-бюджеты, квоты, сроки и правила не назначаем.
- Один файл метода в standards, краткий SKILL + парный workflow YAML со ссылками и версиями; процесс связывает skills по ID. Общие проверки структуры/ссылок/места/ID/результата/чисел используются CLI, доставкой и адаптерами.
- Бизнес-блоки: руководство, операции, маркетинг, продажи, проекты, люди/обучение, финансы, закупки. Они дают маршрут и явно незаполненные определения/источники. Библиотека покрывает 12 операций плана; предметные данные не придумываются.
- Источник P5: разрешённая локальная выгрузка/ручной ввод. Реальное чтение из файлов проверяется; HTTP API и MCP имеют узкий контракт, envelope account/company/scope/completeness/cursor, ошибки и запрет неподтверждённых записей. Live аккаунты отсутствуют. Результат локального сервера — transport test, не live-интеграция.
- P6: один ограниченный CLI tick, пригодный для одноразового cron/systemd вызова. Выключен по умолчанию; включение только явным решением с областью, лимитом и условием. Состояние у соответствующей задачи, lock и повтор без дублей, уведомления только об изменении. Реальный таймер не регистрируем.
- P7: производный индекс над файлами, явные связи/алиасы/источник/hash и тип observation/hypothesis; fallback прямое чтение. Внешняя KB через тот же read-only контракт, без копирования закрытых материалов и без утверждения причинности.
- Профили: Codex CLI 0.160.0/Linux обнаружен; текущий Codex Desktop/WSL — разрешённое явное чтение. Claude Code local/Linux: CLI 2.1.289 обнаружен по абсолютному пути, native discovery/hooks/live пока unverified. Оба имеют тестируемый профиль explicit-file-read, общий контрольный набор и тонкие входы; не выдаём его за native загрузку. Cloud/Windows native не заявляем. Матрица всех 14 возможностей хранится в комплекте и разделяет описанное, локально проверенное, недоступное. Независимость обязательной приёмки не заменяется критиком.
- P8: выпуск → кандидат компании сохраняет company/work/sources/local methods; изменение базового стандарта проверяет местные привязки до допуска. Возврат управляемых методов не откатывает новые задачи. Backup/restore в новый каталог с hash-проверкой. Обратный поток — только заново подготовленные обезличенные файлы метода/учебного примера по allowlist и свидетельству разрешения; автоматического экспорта истории компании нет.

## Этапы и приёмка

P0: уточнение независимым task_plan_reviewer; опыт двух компаний/общий предок/сохранение локального правила.
P1: чистая генерация без перезаписи, общая карта и восемь блоков, File Memory, новый subprocess без recall находит актуальное состояние и новые сущности.
P2: все 12 пар SKILL/YAML, схемы/ссылки/циклы/версии, known-bad числа/полнота/место/ID, evidence привязано к входу/методу/проверке; исправление и повтор исходного случая.
P3: сообщение→задача→ожидание/действие→сводка; отказ/отмена/неясность, соседний получатель, история очереди, эпизоды/аналитика и маркетинговый выход. Полевой эффект остаётся open.
P4: отдельные clones A/B/C и локальный bare remote; конкурентные изменения, обрыв до/после push, устаревший кандидат, повтор, смысловой/текстовый конфликт и сохранение обеих работ.
P5: настоящая разрешённая выгрузка плюс транспортные контрольные серверы; неправильная компания/аккаунт, пагинация/полнота/старая дата/429/timeout/offline/unknown-write; external live open.
P6: одноразовые ticks в subprocess без чата, выключение/lock/повтор/шум/лимит/продолжение, инцидент→ограниченное исправление без ослабления критериев.
P7: вопрос по исходнику/алиасу/связям, изменение hash обновляет ответ; выключенная KB/граф и недоступный источник имеют прямой fallback либо явную остановку.
P8: полный релиз, две компании/местные привязки/семантическое изменение/повтор/грязное дерево/старая сессия; rollback методов сохраняет новую задачу; проверенное восстановление; разрешённое обезличенное предложение; полный независимый task_result_reviewer (не автор и не plan acceptor).

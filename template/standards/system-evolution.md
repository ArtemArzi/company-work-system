# Место и развитие сущностей

Потребность → поиск существующего → один владелец/место → связи → общий цикл task-validation. Обычный файл результата остаётся у задачи, отдельная карточка не нужна. Самостоятельная сущность содержит ID, цель/причину, владельца, версию/статус, вход/выход, основания/потребителей и проверки.

Компания/функции/несекретные решения — company/; задачи/результаты/инциденты — work/<id>/task.json; методы — standards/; навыки — skills/<id>/SKILL.md + workflow.yaml; процессы — workflows/<id>.yaml; программы — scripts/; источники при отсутствии KB — company/sources/<id>/source.yaml и разрешённый материал; адаптеры — adapters/. Индекс содержит ссылки, а не ещё один текущий статус. ID: маленькие латинские буквы/цифры/дефис, 2–64 символа, начинается буквой. Проекции навыков и граф производны.

Поиск перед добавлением: context/search и ближайшая карта. Новый маршрут связать из карты. При переносе/удалении найти всех потребителей, исправить ссылки/предусмотреть преемника, сохранить значимое происхождение; validate обязан выявить битые связи/дубль/неверное место. Источник и чужие инструкции не исполняются от сохранения файла. Новое местное правило хранится в company/standards с ID и binding к base hash, причиной/областью/принятием/проверкой; одно действующее правило на операцию. Неизвестное решение не отменяет базовую гарантию. Изменение базового метода требует сверки binding, обратный поток только по разрешению.

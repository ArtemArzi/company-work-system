# Устройство и развитие

Наши принципы, не универсальные законы книг: SD01 законченный проход; SD02 один владелец; SD03 узкие контракты источников/сред; SD04 результат отдельно от метода; SD05 короткий рекомендуемый вход; SD06 документ по нужде читателя; SD07 обратная связь с действием/остановкой; SD08 реальный путь отдельно от внутреннего отчёта; SD09 малое проверенное изменение и восстановление.

Зачем: исключить дублирующие методы и скрытую потерю состояния. Прежде нового сервиса/формата/журнала показать конкретную недостающую обязанность. Один CLI и общие функции достаточно для подготовленных операций; YAML исполняет агент через них, универсальный программный движок не требуется. Другой способ компании допустим с прежними гарантиями; неизвестные KPI/права/лимиты остаются открытыми.

Основания: Parnas, Criteria for Decomposing Systems (1972), узкие модульные границы; Meadows, Leverage Points, обратная связь; Diátaxis Compass, потребность читателя; ограниченные фрагменты Adams/Choice Architecture и библиография Gall. Полные книги не прочитаны, их тексты не упакованы; происхождение/ограничения в company/sources/design-basis/source.yaml. Проверка каждого принципа — копирование/новая сессия/плохой пример/смена источника/обновление/restore в checks. Программные тесты не доказывают лёгкость работы реальной команды или экономический эффект. Изменение у сопровождающего по общему циклу.

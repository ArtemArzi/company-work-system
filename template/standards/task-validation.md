# Выполнение и проверка

Вход каждого рабочего прохода и запроса актуального общего состояния: preflight → перечитать AGENTS/методы после обновления → context/фактический task.json → общий цикл ниже. Preflight использует принятый общий remote компании, проверяет identity и свежий remote SHA; чистую отстающую копию обновляет только fast-forward, clean local-ahead показывает как pending delivery. При dirty/staged/untracked, незавершённом merge/rebase, detached HEAD, расхождении историй или недоступной общей версии зависимые действия остановить. Чужую работу не auto-commit/stash/reset, изменения не force-push. Нужное самостоятельное действие допускается в явно выбранном отдельном prepare-кандидате; первоначальная незавершённая работа остаётся на месте.

Человеку не поручать обычные fetch/commit/deliver: агент выполняет разрешённые шаги. Обращаться к человеку только за недостающим правом/смыслом или разрешением конфликта. При offline допустим явно обозначенный ответ по local SHA без заявления свежести; общие записи/доставка и решения, требующие свежих данных, ждут связи. После результата — проверка/commit точных разрешённых paths → общий deliver/readback; локально сохранённое не считать общим. Фоновые hooks/таймеры этим правилом не включаются.

Область: законченная содержательная операция. Зачем: уверенность автора и текст PASS не являются проверкой. Метод: актуальный контекст → исходный запрос/критерии/версии → разрешённое действие → точные проверки → критический проход → ограниченное исправление → сохранение → свежая общая версия/доставка/чтение. Единственный цикл; другие стандарты добавляют только свои условия.

Перед действием зафиксировать владельца, ожидаемый выход, неизвестное и входы. Результат обязан иметь первичные основания, период/единицы при расчёте, полноту, ограничения и следующий шаг получателя. Формат, данные и поведение проверяет одна библиотека scripts/validation.py; смысл требует конкретных ссылок, контрпримера и сопоставления с запросом. Семантический критик остаётся свидетельством автора, не независимой гарантией. При материальном риске/сложности требуется отдельная независимая приёмка exact candidate.

task.json содержит hashes входов, стандарта, программы, результата и критического прохода. Изменение зависимости отменяет прежний допуск; неизменённое не перепроверять без требования свежести. Известный плохой пример обязан отвергаться. Не менять принятую acceptance или валидатор ради PASS. Записать сбой и первое неверное допущение, проверить существующий способ, исправить затронутое, повторить проблемный случай. Две попытки без новых фактов останавливают подход.

Verified означает локальную проверку указанного результата. Доставка, применение и эффект отдельны; unknown не равно нулю. Неразрешённое действие/спорный смысл адресовать владельцу. Внешний timeout означает неизвестный исход: readback до повтора; общий CLI внешних записей не делает. Местный способ допускается при прежнем контракте. Изменение этого стандарта — выпуск сопровождающего через template-update.

# Рабочая система компании

[Как устроена работа — визуальное руководство для команды](docs/company-system-guide.html).

Откройте Codex или Claude Code в репозитории компании. Поставьте задачу обычными словами и попросите прочитать [AGENTS.md](AGENTS.md). Например: «Сохрани поручение подготовить сводку заявок; непонятное оставь вопросом» или «Покажи, кто чего ждёт и что делать дальше». Агент находит метод, выполняет разрешённое действие, проверяет, сохраняет и доставляет результат. Файловая память работает независимо от памяти чата.

[Карта компании](company/README.md) → нужный бизнес-блок → [операция](skills/README.md) и её рецепт. У каждой задачи один task.json с историей и продолжением; исходный запрос, источники и результат рядом. Нет подтверждения поручения/источника/права — агент сохраняет ожидание и конкретного владельца решения. Корректные обычные результаты не требуют ручного чтения каждого файла.

Сопровождающему начать с [первой установки и учебного прохода](docs/first-company.md): проверенный пакет → отдельная компания → первая задача → доставка → новая сессия → обновление и восстановление. Затем [точные форматы и команды](standards/runtime.md), [подключения](standards/data-access.md), [правила обновления](standards/template-update.md). Настроить только известное в company/config.yaml: id/owner/permissions.local_work, источники/период/единицы, принятые местные правила и реальные права. Финансы, KPI, бюджет, квоты и неизвестные бизнес-правила по умолчанию не заданы. Источники с ограниченным доступом остаются у provider; роль в тексте не скрывает файл от пользователя repo.

[Наблюдения после доставки](docs/observations.md) фиксируют применение, отсутствие применения или отрицательный эффект для точной версии результата. Проверенный файл и Git readback сами по себе не подтверждают использование командой.

Первый запуск, включая установку Python при его отсутствии: [выбор и подготовка среды](adapters/README.md). Runtime требует Python3.12+, PyYAML6.0.1, Git2.43+; статусы реальных OS проверок указаны в profiles. [Codex](adapters/codex/profile.yaml) и [Claude](adapters/claude/profile.yaml) имеют общую процедуру explicit-file-read и отдельные статусы native. Неизвестные коннекторы, hooks и глобальная память автоматически не подключаются. Локальная выгрузка/transport tests отличаются от live аккаунта.

Проактивный tick выключен до принятой настройки; расписание не устанавливается автоматически. Граф производен, при выключении работает прямое чтение файлов; внешняя KB включается отдельно. Внутренние документы разработки продукта отсутствуют в этом комплекте. Локальные программные проверки, native запуск, общая Git-доставка, полевое применение и эффект различаются; не считать их одним успехом.

[Хуки](hooks/README.md) помогают найти контекст, проверить место нового метода,
обновить карту и сохранить продолжение. По умолчанию они выключены; общий CLI
работает самостоятельно. Создавать и улучшать методы помогает
[company-author](skills/company-author/SKILL.md).

Если документы, карты и ссылки разошлись, использовать
[company-organization](skills/company-organization/SKILL.md): сначала read-only
сверка точных путей и потребителей, затем только разрешённое смысловое решение.


Если правило повторяется в нескольких README и методах, зарегистрировать
[связанные описания](standards/system-evolution.md#связанные-описания-принятого-правила).
Общая проверка обнаружит пропущенный или устаревший блок до сохранения и отправки.
Немаркированный текст агент дополнительно сверяет по смыслу.
